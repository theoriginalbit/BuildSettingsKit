Generate a type-safe Swift file from your projects Xcode build settings.

## Overview

Accessing build settings such as environment-specific values, version numbers, build numbers, bundle identifiers, custom compiler flags, etc. has historically relied on bridging values through `Info.plist` and accessing them at runtime via `Bundle.main.infoDictionary`:

```swift
// Fragile, stringly-typed, and prone to runtime errors:
let version = Bundle.main.infoDictionary?["CFBundleShortVersionString"] as? String ?? ""
let apiURL = URL(string: Bundle.main.infoDictionary?["API_BASE_URL"] as? String ?? "")!
```

**BuildSettingsKit** eliminates stringly-typed dictionary lookups, runtime overhead, and the question of "*How do I correctly behave if this value is nil?*". During build time, BuildSettingsKit reads your build settings directly from the build environment and generates a clean, strongly-typed Swift enum:

```swift
// Safe, compile-time verified, and autocompleted:
let version = BuildConfig.marketingVersion
let apiURL = BuildConfig.apiBaseUrl
```

If a value is missing, or cannot be safely represented as the specified type, a build error will be raised.

BuildSettingsKit is available both as an **automated Swift Package Manager and Xcode build tool plugin** and as a **command-line tool (`gensettings`)**.

## Features

- Supports primitives `String`, `Bool`, `Int`, `Double`, `Float`, `URL`
- Automatically parses space-separated build setting values into strongly-typed arrays (e.g. `[String]` or `[Int]`).
- Declare fallback values with `default` or use optional types (`T?`) that safely resolve to `nil` when unset.
- Use as a build tool plugin or as a standalone CLI tool (`gensettings`).

> [!NOTE]
> `Bool` will recognize `YES`/`NO`, `true`/`false`, or `1`/`0`.

> [!IMPORTANT]
> Arrays elements and optionals wrapped type must be one of the supported types.

> [!NOTE]
> The declared default value will also be validated for the declared type. If it cannot parse an error will be raised against the build.

## Usage

### Define `buildsettings.yaml`

Place a `buildsettings.yaml` file in your target or project directory:

```yaml
typeName: BuildConfig
accessModifier: public
comment: Application build and environment configuration.

settings:
  - key: MARKETING_VERSION
    type: String
    comment: User-facing version string shown in the App Store and Settings.

  - key: CURRENT_PROJECT_VERSION
    swiftName: buildNumber
    type: Int
    comment: Monotonically increasing build number used for App Store submissions.

  - key: PRODUCT_BUNDLE_IDENTIFIER
    type: String
    comment: The bundle identifier of the application target.

  - key: API_BASE_URL
    type: URL
    comment: Base URL for all remote API calls.

  - key: SUPPORTED_ENVIRONMENTS
    type: '[String]'

  - key: FEATURE_FLAG_BETA
    type: Bool
    default: false
    comment: Toggles beta experimental features.
```

### Generated Swift Code

BuildSettingsKit generates a file (by default `BuildSettings.swift`) containing:

```swift
//
// BuildSettings.swift
// Auto-generated by BuildSettingsKit.
// DO NOT EDIT — changes will be overwritten on the next build.
//

import Foundation

/// Application build and environment configuration.
public enum BuildConfig {
	/// User-facing version string shown in the App Store and Settings.
	public static let marketingVersion: String = "1.0.0"

	/// Monotonically increasing build number used for App Store submissions.
	public static let buildNumber: Int = 42

	/// The bundle identifier of the application target.
	public static let productBundleIdentifier: String = "com.example.myapp"

	/// Base URL for all remote API calls.
	public static let apiBaseUrl: URL = URL(string: "https://api.example.com")!

	public static let supportedEnvironments: Array<String> = [
		"staging",
		"demo",
	]

	/// Toggles beta experimental features.
	public static let featureFlagBeta: Bool = false
}
```

### Use in Your Project

```swift
import SwiftUI

struct VersionFooter: View {
    var body: some View {
        VStack(spacing: 4) {
            Text("Version \(BuildConfig.marketingVersion) (\(BuildConfig.buildNumber))")
            Text("API: \(BuildConfig.apiBaseUrl.absoluteString)")
        }
        .font(.caption)
        .foregroundStyle(.secondary)
    }
}
```

## Installation & Integration

### Swift Package Manager Build Tool Plugin

Add BuildSettingsKit to your `Package.swift` dependencies, and attach `BuildSettingsKitPlugin` to your target:

```swift
// swift-tools-version: 6.2
import PackageDescription

let package = Package(
    name: "MyPackage",
    platforms: [.macOS(.v15), .iOS(.v18)],
    dependencies: [
        .package(url: "https://github.com/theoriginalbit/BuildSettingsKit", from: "1.0.0"),
    ],
    targets: [
        .target(
            name: "MyTarget",
            dependencies: [],
            plugins: [
                .plugin(name: "BuildSettingsKitPlugin", package: "BuildSettingsKit"),
            ]
        ),
    ]
)
```

Place your `buildsettings.yaml` (or `.buildsettings.yaml`) in the target's directory or root directory.

### Xcode Project Plugin

1. In Xcode, add BuildSettingsKit as a package dependency:
   - Navigate to **File > Add Package Dependencies...**
   - Enter `https://github.com/theoriginalbit/BuildSettingsKit`
2. Select your application or framework target.
3. Open the **Build Phases** tab.
4. Expand **Run Build Tool Plug-ins** (or click **+ > Run Build Tool Plug-ins**).
5. Add `BuildSettingsKitPlugin`.
6. Add your `buildsettings.yaml` file to your project or target directory.

### Command-Line Tool (`gensettings`)

BuildSettingsKit includes a standalone CLI tool, `gensettings`.

Install using `swift build`:

```sh
git clone https://github.com/theoriginalbit/BuildSettingsKit.git
cd BuildSettingsKit
swift build -c release
cp .build/release/gensettings /usr/local/bin/
```

Run `gensettings`:

```sh
# Auto-discover buildsettings.yaml in current directory and output to BuildSettings.swift
gensettings generate

# Specify custom config and output path
gensettings generate --config path/to/config.yaml --output Sources/MyTarget/GeneratedSettings.swift

# Supply or override environment variables directly
gensettings generate --env API_BASE_URL=https://staging.example.com --env FEATURE_ENABLED=true

# Emit Xcode-compatible diagnostics for build scripts
gensettings generate --xcode
```

#### CLI Options

| Option | Flag | Description |
| :--- | :--- | :--- |
| `--config` | `-c` | Path to the YAML configuration file (auto-discovered if omitted). |
| `--output` | `-o` | Path for the generated Swift file (defaults to `BuildSettings.swift`). |
| `--env` | `-e` | Environment overrides passed as `KEY=VALUE` pairs. |
| `--cli` / `--xcode` | | Output diagnostics formatted for terminal (`--cli`) or Xcode Issue Navigator (`--xcode`). |
| `--verbose` | `-v` | Increase diagnostic verbosity (`-vvv`). |

## Configuration Reference

BuildSettingsKit is configured via YAML. The tool automatically discovers any of the following filenames in the working or target directory:
- `buildsettings.yaml`
- `buildsettings.yml`
- `.buildsettings.yaml`
- `.buildsettings.yml`

### Top-Level Configuration

| Key | Type | Default | Description |
| :--- | :--- | :--- | :--- |
| `typeName` | `String` | `"BuildSettings"` | Name of the generated enum namespace type. |
| `outputFileName` | `String` | `"BuildSettings.swift"` | Name of the generated file (used when running CLI without `--output`). |
| `accessModifier` | `String` | `"internal"` | Default access modifier for the enum and properties (`public`, `package`, `internal`, `fileprivate`, `private`). |
| `comment` | `String` | `nil` | DocC documentation comment attached to the enum type. |
| `settings` | `Array` | *(Required)* | List of setting definitions to generate. |

### Setting Definition

Each item under `settings` supports:

| Key | Type | Default | Description |
| :--- | :--- | :--- | :--- |
| `key` | `String` | *(Required)* | The name of the Xcode build setting or environment variable (e.g. `MARKETING_VERSION`). |
| `type` | `String` | *(Required)* | Swift type of the property (`String`, `Bool`, `Int`, `Double`, `Float`, `URL`, `[T]`, `T?`). |
| `swiftName` | `String` | camelCase of `key` | Custom Swift property identifier name (e.g. `buildNumber` for `CURRENT_PROJECT_VERSION`). |
| `default` | `String` | `nil` | Fallback value to use if the environment variable is not present. |
| `accessModifier` | `String` | Root `accessModifier` | Override access modifier specifically for this property. |
| `comment` | `String` | `nil` | DocC documentation comment attached to this static property. |

## Supported Types

| Setting Type | YAML Example | Supported Formats / Notes | Generated Swift Type |
| :--- | :--- | :--- | :--- |
| `String` | `type: String` | Any string literal. | `String` |
| `Bool` | `type: Bool` | Case-insensitive: `YES`, `NO`, `true`, `false`, `1`, `0`. | `Bool` |
| `Int` | `type: Int` | Integer string representations (e.g. `42`). | `Int` |
| `Double` | `type: Double` | Floating-point string representations (e.g. `12.5`). | `Double` |
| `Float` | `type: Float` | Floating-point string representations (e.g. `12.5`). | `Float` |
| `URL` | `type: URL` | Valid URL string (generates `URL(string: "...")!`). | `URL` |
| Arrays | `type: '[String]'` or `type: '[Int]'` | Space-delimited string of items (e.g. `"iphoneos iphonesimulator"`). | `Array<T>` |
| Optionals | `type: 'String?'` or `type: '[URL]?'` | If key is missing and no default is provided, emits `nil`. | `Optional<T>` |

> [!NOTE]
> Arrays element and optionals wrapped type must be one of the other supported types.
